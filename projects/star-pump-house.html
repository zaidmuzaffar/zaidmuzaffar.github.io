01 / the problemThe problem

Star Pump House sells water pumps, wire, safety cable and hardware, and also supplies other shops wholesale on credit. Everything lived in notebooks: stock, daily sales, customer credit (udhaar), supplier bills and the accounts of the shops we supply.

That caused the same questions every day, with no quick answer:

  • What is running low, and what is already on its way from a supplier?
  • Who owes us money, how much, and since when?
  • How much cash should be in the drawer tonight?
  • What did we actually earn this month after costs and expenses?
CONSTRAINTS

It had to cost nothing to run, work on a laptop and a phone at the counter, be simple enough for someone who isn't a developer, and keep each account's data private. I was a beginner at coding when I started.

02 / my roleMy role

I did everything end to end: gathered requirements from the counter, designed the screens, built and tested every page, set up security and deployment, and kept shipping improvements based on real feedback. My brother runs the shop and is the main user, which made every rough edge visible fast.

03 / what i builtWhat I built

Stock by categoryPumps, wire, safety cable and other items, each with its own fields. Wire and cable are tracked in feet; bundle counts drop automatically as footage is sold.
Sell flowMulti-product bills, cash or credit, partial payments with a remaining-balance tracker, and a guard that blocks selling above the listed price.
Credit (udhaar)A pending-payments page grouped by bill, with bulk "mark received", and received records kept visible with a green badge.
Suppliers & wholesalePurchases, supplier balances and separate accounts for the shops we supply.
Cash closingA daily count of the drawer that knows exactly how much should be there.
Profit & chartsProfit after costs and expenses; daily, weekly, monthly and overall charts with averages, highs and change.
Salesman loginA separate role that can sell but cannot see the accounts — enforced by Firestore security rules, not just hidden in the UI.
ReceiptsPDF receipts and customer statements generated in the browser, shareable on WhatsApp.
Ask AIAn assistant that answers questions from the shop's own records in English or Roman Urdu and opens pre-filled forms that the owner confirms before saving.

Plus dark mode, a phone layout with a "laptop view" toggle, voice input, backup & restore and a morning summary report.

04 / architectureArchitecture

BrowserPlain HTML, CSS and JavaScript modules — no build step
Firebase AuthEmail/password; session-only login
Cloud FirestoreAll data under users/{uid}/…
Firebase HostingStatic files on a free global CDN

The AI assistant uses Gemini through Firebase AI Logic with function calling: the model can look up records and propose an action (a sale, a payment received, a new product), but it only ever opens a pre-filled form. A person presses Save.

Abuse protection uses App Check with reCAPTCHA Enterprise, and the browser API key is restricted to the app's own domains.

05 / key decisionsKey decisions

DecisionWhy
Firebase instead of MongoDB + Node.jsNo server to run or pay for; Auth, database and hosting in one free plan — right for a one-person project.
Multi-tenant data under users/{uid}Every signed-up account sees only its own data; this is also what lets the public demo sit safely next to the real shop.
Roles in security rulesA salesman account is limited on the server, so hiding a button is never the only protection.
AI proposes, human savesMoney records must be correct; the model fills forms but never writes on its own.
Session-only loginA shared counter laptop should not stay signed in after the browser closes.
Client-side PDFsReceipts work without a server and cost nothing.

06 / challengesChallenges

Selling by the foot

Wire is bought in bundles but sold by length. I modelled price-per-foot and footage, and made the bundle count fall automatically as feet are sold, so stock always matches the shelf.

One bill, many products, partial payment

A customer may buy three items, pay part now and the rest later. The remaining balance is split proportionally across the items, kept in sync between Sales and Pending Payments, and the rows are grouped back into one bill by their shared timestamp.

Free-tier limits

Firestore's free plan allows a fixed number of reads per day. I learned how page loads translate into reads, watched usage in the console, and planned date-limited loading for when the sales history grows.

Security as a beginner

I learned that a Firebase API key is meant to be public, and that real protection comes from security rules, App Check and domain restrictions — and set up all three.

07 / how i shipped itHow I shipped it

I built it in small, numbered releases — 57 so far. Each one changed only what was needed and was tested in a headless browser against a stubbed Firebase with seeded fake data before it reached the shop. Feedback from the counter decided the next release: a slow page, a confusing message or a missing field became the next update.

08 / resultsResults

  • The shop uses it every day in place of paper registers.
  • Stock, credit and profit questions are now answered in seconds instead of by flipping through notebooks.
  • It runs on Firebase's free plan, so hosting costs nothing.
  • A public demo with fake data lets anyone try every screen without touching real records.

09 / what i learnedWhat I learned

  • Designing data models around how a business actually works (feet vs units, partial payments, wholesale).
  • Thinking about security on the server side: rules, roles, App Check.
  • Shipping in small increments with testing, and treating user feedback as the roadmap.
  • Using an LLM safely in a money-handling app: tools, not autonomy.

12 / documentationDocumentation

Repository structure

src/ holds the web app (HTML pages, CSS, JavaScript modules, Firebase config). docs/ holds the full case study, UI screenshots and project overview as PDFs.

Run it locally

  1. Clone github.com/zaidmuzaffar/star-pump-house.
  2. Create a Firebase project; enable Email/Password Auth and Firestore; paste your web config into the Firebase config file.
  3. Install the CLI: npm install -g firebase-tools, then firebase login.
  4. Serve locally with firebase serve, or deploy with firebase deploy.

Data model

Each account's collections — products, sales, upcoming products, suppliers, shops, expenses and more — live under users/{uid}, which keeps accounts isolated and makes per-user security rules simple.
