01 / why i built itWhy I built it

Doing the same server tasks by hand is slow and error-prone: a missed step when creating a user, a forgotten environment variable, a log nobody reads until something breaks. The DevOps idea I wanted to practice is simple — if you do it twice, script it.

02 / what the scripts doWhat the scripts do

User access managementCreate, modify and remove users and their permissions consistently.
Environment setupSet up environment variables and configuration the same way every time.
Process monitoringCheck that important processes are running and report the ones that aren't.
Log parsingScan logs automatically and pull out the lines that matter.
Health checksRoutine checks of system health to streamline maintenance.
Version controlScripts and configuration documentation managed in Git and GitHub.

03 / designDesign

Each script does one job and can be run on its own or combined with the others. Keeping them modular made them easier to test, reuse and document — the same principle behind larger automation and infrastructure-as-code tools.

The foundation came from my Operating Systems course, where I worked in Ubuntu from the command line throughout: files and directories, processes, threads, concurrency and scheduling.

04 / what i learnedWhat I learned

  • Writing Bash that is safe to run more than once.
  • Thinking in terms of repeatable operations instead of one-off commands.
  • Documenting operational work so someone else can run it.

This is the base I'm building on for DevOps: next come CI/CD pipelines, containers and infrastructure as code.
